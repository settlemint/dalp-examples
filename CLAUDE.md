# DALP Examples — agent notes

This is a Turborepo of frontend examples for the SettleMint Digital Asset
Lifecycle Platform (DALP). It mirrors the toolchain of the main `dalp` repo
(bun, turbo, oxlint, oxfmt, TanStack Start) but stays frontend-only.

## Structure

- `apps/*` — runnable example applications. Each is independently deployable
  to Vercel.
- `packages/dalp-client` — typed wrapper around the DALP HTTP API. Every app
  should import from here rather than calling `fetch` directly.
- `packages/theme` — shared Tailwind v4 preset + tokens.
- `packages/tsconfig` — shared TS configs (`base.json`, `react.json`).

## Conventions

- Bun + Turborepo workspaces. Always use `bun run --filter <name> <script>` to
  scope to one app/package.
- TanStack Start with file-based routing. The `routeTree.gen.ts` files are
  generated by the dev server and checked in as stubs so type-checks pass
  before the first run.
- Conventional Commits enforced by `commitlint` in CI.
- Every PR that touches a published package or app needs a Changeset
  (`bun run changeset`).

## Adding a new example

1. Copy `apps/hello-dalp` to `apps/<name>` and rename in `package.json`.
2. Add `vercel.json` and `.env.example`.
3. Add a Deploy button to the example's `README.md`.
4. Add a row to the root `README.md` table.
5. Run `bun run changeset`.

Keep examples small. One focused idea per example. If something is shared
across multiple examples, push it into `packages/dalp-client` or
`packages/theme` — do not create a kitchen-sink `packages/shared`.

## Do not

- Add a backend/database/migrator. This repo is frontend-only on purpose.
- Add multiple framework choices. Every example uses TanStack Start.
- Add custom CI per app. The root `ci.yml` already builds, lints, typechecks,
  and tests every workspace.
